# Trello Creative Producer

## Procedure

1. Read `references/onboarding.md` and any stored producer contract. Use `ask_user` to open with **“What should I produce this run?”** and offer: produce every eligible card in `Design / Video Production`; produce one selected card; re-render one selected card (the operator types the card name or the asset path in free text). Scheduled runs reuse the stored contract and skip this step. Complete this step when one run scope is selected.

2. Ask only the remaining popups in `references/onboarding.md`. Always ask **“Which render strategy should I use?”** with `AI generation only`, `Deterministic HTML/CSS template only (Recommended for text-heavy posts)`, and `AI background + HTML/CSS overlay`. Ask **“Regeneration budget?”** with `2 attempts (Recommended)`, `3 attempts`, or `Unlimited (cost warning)`. When the contract has a single-image policy and any selected card still has `Format: carousel`, ask **“Image policy override?”** with `Downgrade to single image (Recommended)` or `Force carousel anyway`. If a card’s `Creative brief` lacks a provider/model, ask for one. Never pick a provider on the agent’s own. Complete this step when every required contract field has an answer.

3. Show a compact run plan in chat (scope, eligible cards, render strategy, regeneration budget, image policy overrides, providers/models). Then `ask_user` with `Use this plan (Recommended)`, `Change answers`, and `Cancel run`. If answers change, ask only the affected questions and re-show. Complete this step only after explicit confirmation.

4. Verify only the connectors this run needs. Resolve the confirmed board plus `Design / Video Production`, `Ready for Review`, and `Blocked / Failed` lists. Verify image and video capabilities only for asset types actually required. Complete this step when Trello and the required media capability are ready or the exact blocker is reported.

5. Select only cards in `Design / Video Production` whose `Draft status: complete`, `Creative status: queued`, asset type, brief, and confirmed provider/model are present. Respect the per-run limit; skip instruction/template cards. Re-read each card fully and parse `Format`, `Visual concept`, `Source signals`, `Source ownership`, and `Source-use policy`. Apply the format compliance rule: `text` skips asset generation and routes directly; `text + one image` produces exactly one asset; `carousel` is downgraded to a single image when the contract pins `single_image_only: true`; carousel allowed only when the contract permits, capped at 10 panels. Complete this step when every eligible card has a clear render plan.

6. For each card, have the current model turn the approved draft and creative brief into an original generation prompt. Do not copy source authors’ artwork, branding, faces, screenshots, or distinctive layouts. Include composition, subject, environment, lighting, palette, mood, aspect ratio, placement, and negative constraints. Complete this step when the prompt describes the intended asset without credentials or private instructions.

7. Apply the confirmed render strategy for each card:
   - **AI generation only** — call `image_generate` (or `video_generate`) with the exact configured model and output settings.
   - **Deterministic HTML/CSS template only** — load the contract-specified template (default `templates/lead-magnet-card.html`) and the Playwright renderer (`templates/render.js`), fill in the brand colors, typography, and structured text from the card’s `Visual concept` and `Final draft`, and render a 1080×1080 (or contract-specified) PNG.
   - **AI background + HTML/CSS overlay** — generate the background with the configured model, then composite the deterministic template on top so text is never generated by the model.
   Save outputs under `media/content-pipeline/<slug>/<fingerprint>/`. Complete this step when every requested file exists locally or a precise provider error is available.

8. Inspect every generated file with `view_image` (or a video viewer). Check relevance, legibility, aspect ratio, accidental logos, unsupported claims, obvious artifacts, and safety. For deterministic renders, also run a layout-integrity check: compute bounding boxes of headline, subhead, body, and CTA via `playwright.evaluate` and assert non-overlap; assert all text fits inside the canvas; assert the accent color matches the contract. Regenerate only within the confirmed budget. **If a regeneration produces the same defect twice, switch to the deterministic fallback instead of looping on the same failure.** Complete this step when all assets pass or the job is blocked with a clear reason.

9. Preview every asset in chat. Then `ask_user` with `Save and route (Recommended)`, `Regenerate with different prompt`, `Switch to deterministic template`, `Skip this card`, and `Pause and inspect manually`. Revise or skip the operator’s choice and re-preview. Scheduled runs skip this step and write directly with verification. Complete this step when the set to save is explicit.

10. Apply approved assets in Trello: update the card while preserving prior idea and draft content; append the prompt summary, provider/model, local asset path(s), MIME/file type, dimensions or duration, SHA256 hash, accessibility/alt-text suggestion, generation attempts, timestamp, and `Creative status: complete`. Move successful cards to `Ready for Review` and set `Review status: pending`. On failure, move the card to `Blocked / Failed` with a sanitized error and a recovery suggestion. Complete this step when every saved card has exactly one verified destination.

11. Verify the deliverable: re-read each moved card; assert the destination list, the asset record, the file hash, the file size, and the next-stage flags; assert the local asset path still exists with `ls -la` and the recorded hash matches `sha256sum`. If a card is missing, the destination is wrong, the asset record is incomplete, or the hash no longer matches the file, report `incomplete: produced N of M, Trello shows N'` with the mismatches and stop. Complete this step when the run is fully verified.

12. If recurring mode was selected, list existing automations, restate the schedule and contract, obtain a yes, then create or update one producer-only `agentTurn` job and force one visible test. Scheduled runs reuse the stored contract, skip popups and previews, write directly with verification, and pause when the contract is incomplete or the render budget is exhausted. The job must not scout, draft copy, approve, stage social media, or publish. Complete this step when the routine is verified or a precise blocker is reported.

13. Persist state only after verified delivery: the confirmed contract, processed card fingerprints, last run timestamp, asset hashes, and automation job ID. Never store credentials, OAuth data, source post bodies, or expiring social upload URLs. Complete this step when a repeat run cannot duplicate the same asset and can reproduce the operator’s render instructions.

## Guardrails

- This skill owns `Design / Video Production` → `Ready for Review` or `Blocked / Failed`. It never approves, schedules, or publishes.
- Use popup onboarding for interactive runs and preview every asset before any Trello write.
- Never pick a paid provider or model on the agent’s own. Always ask or reuse a confirmed contract value.
- Never copy source authors’ artwork, branding, faces, screenshots, or distinctive layouts.
- Single-image contracts downgrade carousel briefs automatically; surface every downgrade in the preview.
- Deterministic renders must pass the layout-integrity check before saving; switch to the deterministic fallback after two failed regenerations instead of looping on the same defect.
- Final media stays local until the Publisher stages it after approval.
- Actual Trello and filesystem state override worker reports.
